| 풍향 표시 | 숫자·문자 표시 | 평면도 북쪽 화살표, 나침반, 불어오는 방향·이동 방향 화살표 |
| 가구 | 이동·크기 변경(겹침 허용 가정) | 이동·크기 변경·**추가·삭제**, 겹침 금지(`ff85a9a`에서 이미 반영, §6.1) |

### 바뀌지 않는 것
Stable Fluids Solver, 추적 물질(Passive Scalar) 수송, **목적함수(60초 뒤 잔류율 최소화)**, 환기 취약 후보 판정, 보안·교육용 제약, `PRODUCT.md`.

### 기존 2개 창문 결과와 달라지는 부분 (명시)
- **창 2개 계산은 달라지지 않는다.** 새 다중 창문 모델은 창이 2개일 때 기존 모델과 수식이 같아지도록 설계하며, 기본 평면도·기본 가구·서풍 3 m/s에서 개방률 0·50·100% 조합 9개의 잔류율이 개정 전과 같아야 한다(§9의 16).
- 달라지는 것은 **창이 3개 이상일 때(신규 동작)**, **탐색에 25개 조합이 쓰이는 점**(0·50·100% 조합은 25개 안에 그대로 포함됨), **흐름 요약 표기**(유입 창·유출 창이 여럿일 수 있음), **개방률이 양수여도 개구 폭이 0칸이 되는 아주 작은 창은 닫힌 것으로 보는 점**이다.

## 1. 이번 작업의 목표

사용자가 가상 아파트 평면도에서 가구 위치, 창문 배치와 개방률, 풍향·풍속을 바꾸면 2D 경량 유체 계산이 유동장을 다시 계산한다. 여러 창문 개방 조합을 자동으로 비교해 상대적으로 환기가 유리한 조건을 추천하는 **작동형 프로토타입**을 만든다.

목적은 경량 유동 Solver와 자동 최적화를 연결할 수 있는지 확인하는 것이다. 실제 환기 성능이나 CFD 수준의 정량 정확도를 검증하는 것은 목적이 아니다. 개정으로 추가되는 다중 창문 모델의 정량 정확도도 이번 교육에서 검증하지 않는다.

## 2. PRODUCT.md와의 충돌 확인

**제품 방향을 바꿔야 하는 충돌은 없다.** 개정 내용도 PRODUCT.md의 정의("창문 개방 조합 자동 탐색", "창문 개방률 설정")와 제품 경계 안에 있다. PRODUCT.md는 이번 단계에서 수정하지 않는다.

| 항목 | 판정 | 내용 |
|---|---|---|
| 목적·사용자·핵심 루프 | 일치 | 창문을 바꿔 가며 결과를 비교하는 루프가 더 풍부해질 뿐이다. |
| 정량 검증 제외 | 일치 | 다중 창문 모델도 정량 검증에서 제외한다. |
| 물리 일관성 | 일치 | 불투과 경계, 입자의 속도장 사용, 조건 변경 시 계산영역·경계조건 갱신을 유지한다. 창문을 편집하면 고체 마스크와 경계조건이 갱신된다. |
| 보안·교육용 제약 | 일치 | 변화 없음. |

용어: **잔류율**은 조건 전체를 비교하는 점수이고, **환기 취약 후보**는 한 조건 안에서 실내 어디가 취약한지 보여 주는 지도이다.

## 4. 사용자 결과

사용자가 앱을 열면 **가상 아파트 평면도**가 보이고, 벽·방문·창문(기본 2개)·가구, 그리고 북쪽을 가리키는 화살표가 표시된다. 사용자는 다음을 할 수 있다.

1. 가구를 끌어 옮기고 크기를 바꾸고, 새 가구를 추가하거나 삭제한다. 가구끼리·벽과 겹치는 위치는 거부되고 안내가 뜬다.
2. 창문을 끌어 옮기고 크기를 바꾸고, 창을 추가하거나 삭제한다(2~6개). 놓으면 그때 유동이 다시 계산된다.
3. 각 창의 개방률을 0~100%에서 5% 단위로 조절한다. 나침반으로 풍향을 정하고, 바람이 불어오는 쪽과 이동하는 방향을 화살표로 확인한다.
4. 조건을 바꾸면 곧바로 유동이 다시 계산되고, 입자가 계산된 속도장을 따라 움직이며 환기 취약 후보 지도가 표시된다.
5. "최적 조합 탐색"을 누르면 먼저 **탐색 계획**(단계 수, 총 조합 수, 계산 대상 조합 수)이 보이고, 조합이 과도하면 단계가 줄어든다는 안내나 탐색할 창을 고르는 선택이 나온다. 계산이 끝나면 잔류율이 낮은 상위 3개가 현재 조건과 함께 표로 나온다.
6. 1위 조건과 현재 조건을 나란히 놓고 유동과 취약 후보 지도를 비교한다. 화면에는 "교육용 상대 비교이며 실제 환기 성능을 검증한 것이 아니다"라는 안내가 항상 보인다.

## 6. 동작 계약

### 6.1 평면도·가구·고체 영역
- 평면도는 하나이며 벽, 방문, 창문이 구분되어 보인다. 기본 평면도의 창문은 2개이고 서로 다른 외벽(서쪽, 남쪽)에 있다. 각 창문은 해당 외벽에 난 실제 개구부로 처리되어, 열린 만큼 벽이 뚫리고 닫힌 만큼 벽으로 막힌다. 창문이 편집되면 고체 영역(마스크)이 즉시 갱신된다.
- 벽과 가구는 유동이 통과할 수 없는 고체이다.
- **가구 배치(`ff85a9a`에서 이미 반영, 이번 개정에서 스펙을 현재 동작에 맞춤):** 가구는 사각형이고 아파트 실내에서만 움직이고 크기를 바꾼다. 다른 가구, 벽, 아파트 밖, 창문·방문 개구부와 겹치는 이동·크기 변경·추가는 거부하고 마지막 유효 상태를 유지하며 짧은 안내를 보여 준다. 경계가 맞닿는 것은 허용한다. 가구 종류(침대, 소파, 책상, 식탁, 수납장)를 골라 평면도의 원하는 위치나 빈 공간에 추가하고, 빈 공간이 없으면 추가하지 않고 안내한다. 이동·크기 변경·추가는 같은 충돌 판정을 쓴다.
- **가구 삭제(신규):** 선택한 가구를 삭제할 수 있다. 삭제하면 고체 영역과 유동 결과가 갱신되고, 이미 실행한 탐색 결과는 "조건이 바뀌었습니다"로 표시된다. 삭제는 되돌릴 수 없다(§7 가정 17).

### 6.2 창문, 개방률, 바람, 다중 창문 경계조건
- 각 창은 **0~100% 범위에서 5% 단위**로 개방률을 **설정**한다(0%는 막힌 벽과 같다). 계산에는 격자에 **실제로 적용된 개방률**이 쓰인다.
  - **적용 규칙(기존 격자 처리 그대로이며 알고리즘을 바꾸지 않는다):** 열린 칸 수 = 창 길이(칸) × 설정 개방률을 가장 가까운 정수로 반올림한다(.5는 올림). 열린 구간은 창의 가운데에 두며, 창 길이와 열린 칸 수의 차이가 홀수 칸이면 시작 쪽으로 반 칸 치우친다. **적용 개방률 = 열린 칸 수 ÷ 창 길이(칸)** 이다.
  - **구분 표시:** 창마다 "설정 55% → 적용 56% (9/16칸, 1.5 m)"처럼 설정 값, 적용 값, **열린 칸 수와 열린 폭(m)** 을 함께 보여 준다. 두 값이 다르면 그 사실이 보인다.
  - **같은 개구부 안내:** 격자가 5%보다 거칠어 서로 다른 설정이 같은 열린 칸 수가 될 수 있다. 현재 설정이 이웃한 설정과 같은 열린 칸 수가 되면 "이 창에서는 10~15%가 같은 열린 폭(2칸)으로 계산됩니다"처럼 같은 개구부가 되는 설정 범위를 안내한다.
  - 설정이 양수여도 열린 칸 수가 0이면 닫힌 것으로 보고, "설정 5% → 적용 0%(닫힘)"으로 표시한다.
  - 자동 탐색의 단계(25% 간격)는 창 길이가 최소(4칸)일 때도 서로 다른 열린 칸 수가 되므로, 탐색 단계끼리는 같은 개구부가 되지 않는다.
- 풍향은 평면도 기준 방향(도 단위)이고 정의는 §6.9를 따른다. 풍속은 수동 입력한다.
- **다중 창문 경계조건(신규, 교육용 단순 규칙):**
  - 각 창은 자신이 놓인 **외벽의 방향**에 따라 풍압 값을 갖는다. 바람을 정면으로 받는 벽의 창은 가장 높고, 측면 벽은 0, 바람 반대쪽 벽은 음수이다. 같은 외벽의 창은 같은 값이다. (기존 규칙을 그대로 쓰며 실제 풍압계수가 아니다.)
  - 실내에는 하나의 기준 압력이 있고, **열린 모든 창의 유입량과 유출량이 같아지도록**(들어오는 양 = 나가는 양) 정해진다.
  - 창마다 **자신의 열린 폭과 (창의 풍압 − 실내 기준 압력)** 로 유량을 따로 계산한다. 풍압이 실내 기준보다 높은 창은 유입, 낮은 창은 유출, 같으면 흐름이 없다. 열린 폭이 넓고 풍속이 클수록 유량이 커진다.
  - **경계조건 전달(Solver 알고리즘은 바꾸지 않고, 이미 쓰는 경계조건 종류만 사용한다):**
    - **유입 창:** 그 창의 모델 유량을 창의 열린 폭으로 나눈 **유입 속도**를 개구부 바깥 경계에 실내 방향으로 지정한다. 창마다 자기 속도를 받으므로 **유입 창 사이의 유량 분배는 모델과 정확히 같다.** 유입 공기의 추적 물질 농도는 0이다.
    - **유출 창:** 개구부 바깥 끝에 **압력 고정 경계**를 둔다. 유량을 지정하지 않으므로 총 유출량은 총 유입량과 같지만(비압축성), **유출 창이 여럿이면 창 사이의 유량 분배는 Solver의 압력 계산이 정한다.** 이 분배는 모델 유량과 다를 수 있고 맞추지 않는다(한계). 유출 창이 하나면 모델과 같다.
    - 창 2개(유입 1개, 유출 1개)에서는 기존 방식과 완전히 같다.
    - 유출 창에도 속도를 지정해 분배를 맞추는 방식은 Solver의 경계조건 구성을 바꿔야 하므로 쓰지 않는다. 이 한계를 줄여야 하면 먼저 영향과 이유를 보고하고 별도로 승인을 받는다.
  - **창별 흐름 확인(신규):** 창마다 다음을 화면에서 볼 수 있다. ① 역할(유입·유출·흐름 없음)과 방향, ② 풍압 값, ③ 설정·적용 개방률과 열린 폭, ④ **모델 유량**(m²/s, 단위 깊이당), ⑤ **Solver 결과에서 개구부 경계 면을 지나는 유량을 합해 측정한 적용 유량**, ⑥ 유입 창은 유입 속도. 유출 창은 모델 유량과 적용 유량의 차이를 함께 보여 주며 Solver의 분배를 보정하지 않는다. 적용 유입량의 합과 적용 유출량의 합은 허용 오차 안에서 같아야 한다(정량 검증은 제외).
  - **통과 흐름이 없는 경우:** 열린 창이 2개 미만(단면 환기는 모델링하지 않음), 풍속 0, 열린 창의 풍압이 모두 같은 경우. 이때 잔류율은 100%이다.
  - **2개 창일 때는 기존 모델과 같은 결과**를 내야 한다(회귀 기준, §9의 16).
- 창의 위치(외벽 따라 어디에 있는지)는 풍압이 아니라 **개구부가 뚫리는 자리**로 반영되어 유동 경로를 바꾼다.

### 6.3 유동 계산
- 2D 비압축성 Stable Fluids로 계산하고, 고체 경계에서는 불투과 조건을 적용한다. **Solver 알고리즘은 바꾸지 않는다.** 바뀌는 것은 Solver에 넘기는 경계조건과 고체 영역뿐이다.
- 가구, 창문 배치·개방률, 풍향·풍속이 바뀌면 계산영역과 경계조건을 갱신해 다시 계산한다.
- 질량보존을 정량 검증하지는 않지만, 기본적인 질량보존 구조(속도장의 발산을 줄이는 처리)와 벽면 불투과는 유지한다.

### 6.4 시각화
- 입자는 계산된 속도장을 따라 움직인다. 속도장과 무관한 장식용 움직임은 쓰지 않는다.
- 벽·가구 안으로 들어가는 입자는 없다.
- 입자 추적을 우선 구현하며, 유선은 선택 요소이다.

### 6.5 환기 취약 후보 분석
- 계산 시작 시 실내 모든 유체 영역에 같은 농도의 추적 물질을 채우고, 창문으로 들어오는 공기의 농도는 0으로 한다.
- 정해진 계산 시간이 지난 뒤 남아 있는 농도가 높은 구역을 "환기 취약 후보"로 지도에 표시한다.
- 표시 기준은 실내 평균 대비 상대 기준이며 정확한 임계값은 가정이다(§7).

### 6.6 자동 탐색과 추천
- 탐색 단계의 기본값은 **0%, 25%, 50%, 75%, 100%** 이다(5단계). 창이 n개이면 총 조합은 5의 n제곱이다(창 2개 → 25조합).
- **탐색 계획 안내:** 탐색을 시작하기 전에 단계 수, 총 조합 수, **계산 대상 조합 수**를 보여 준다. 계산 대상은 통과 흐름이 생기는 조합(열린 창이 2개 이상이고 풍압이 모두 같지 않음)이다. 통과 흐름이 없는 조합은 계산하지 않아도 잔류율이 100%로 정해지므로 표에는 포함하되 계산을 생략할 수 있고, 결과는 모두 계산했을 때와 같다.
- **조합 수 제한(계산 대상 30개 이하, §7 가정 10):** 5단계로 계산 대상이 30개를 넘으면 **5 → 3단계(0·50·100%) → 2단계(0·100%)** 순으로 줄이고, 줄였다는 사실과 새 조합 수를 사용자에게 알린다. 2단계로도 넘으면(창이 많을 때) **탐색할 창을 사용자가 고르게** 하고, 고르지 않은 창은 현재 개방률로 고정한다. 조용히 줄이지 않는다.
  - 예(모든 창의 풍압이 서로 다른 최대 경우의 계산 대상 수): 창 2개 5단계 25조합(계산 16), 창 3개는 5단계가 125조합(계산 112)이라 3단계 27조합(계산 20)으로 축소, 창 4개는 3단계로도 81조합(계산 72)이라 2단계 16조합(계산 11)으로 축소, 창 5개는 2단계 32조합(계산 26 이하), 창 6개는 2단계 64조합(계산 57 이하)이라 상한을 넘을 수 있어 탐색할 창 선택. 외벽은 4개뿐이라 창이 5개 이상이면 같은 벽을 공유하는 창이 생기고, 그 창들 사이에는 흐름이 없어 실제 계산 대상은 이보다 적다.
- **탐색 범위 표시(결과에 항상 표시):**
  - **전체 평가:** 모든 창을 기본 5단계(0·25·50·75·100%)로 모든 조합 평가한 경우. "5단계 전체, 25조합 평가"처럼 표시한다.
  - **제한 평가:** 단계를 줄였거나(3단계·2단계) 일부 창만 탐색한 경우. "제한 평가"로 표시하고, **실제 사용한 개방률 단계**(예: 0·50·100%), **평가한 조합 수와 5단계 전체 조합 수**(예: 27개 / 125개), 탐색한 창과 현재 개방률로 **고정한 창**을 함께 보여 준다.
  - 통과 흐름이 없어 계산을 생략한 조합도 평가 조합 수에 포함하되, 계산한 수와 구분해 표시한다(예: 27개 평가, 20개 계산).
  - 추천 문구는 "**탐색한 범위 안에서 가장 유리한 조합**"이다. 제한 평가의 결과를 **전체 최적해로 표현하지 않는다.** 전체 평가도 25% 간격 격자 안의 결과이며, 5% 단위의 모든 값을 확인한 것은 아니다.
  - 표시한 탐색 범위는 상위 3개 표, 추천 문구, 나란히 비교 화면에서 모두 같은 내용으로 보인다.
- 모든 조합은 같은 가구 배치, 같은 창 배치, 같은 풍향·풍속, 같은 초기 농도, 같은 계산 시간으로 비교한다.
- 목적함수는 **정해진 시간 뒤 추적 물질 잔류율(남은 총량 ÷ 처음 총량)이 낮을수록 유리**하다는 것이며 바꾸지 않는다.
- 결과는 잔류율이 낮은 상위 3개와 현재 조건을 한 표로 보여 준다. 각 행에 **모든 창의 개방률(적용된 열린 칸 수 포함)**과 잔류율, 현재 조건 대비 차이를 표시한다.
- **현재 조건**은 사용자가 자동 최적화를 실행하는 시점에 설정되어 있는 모든 창의 개방률(5% 단위)과 풍향·풍속이다. 현재 개방률이 탐색 단계에 없는 값(예: 35%)이면 **현재 조건을 따로 계산**해 현재 행으로 보여 준다. 추천은 탐색한 조합 안에서만 고른다. 추천이 현재 조건과 같으면 "(현재 조건과 같음)"으로 표시한다.
- 잔류율이 같은 조합의 순서는 열린 정도의 합이 작은 쪽이 먼저이고, 그다음은 창 순서이다. 같은 입력이면 항상 같은 순위가 나온다.
- 최적 조건과 현재 조건을 나란히 놓고 유동과 취약 후보 지도를 비교한다. 두 조건의 잔류율 차이가 작으면 "유의한 차이 없음"으로 표시한다.
- 창을 편집하거나 가구·풍향·풍속·개방률이 바뀌면 이미 나온 탐색 결과는 "조건이 바뀌었습니다"로 표시한다.

### 6.7 표현 원칙
- 결과는 "상대적으로 유리한 조건"으로만 표현한다. "환기 성능이 검증되었다", "실제 아파트에서 X% 개선된다" 같은 표현은 쓰지 않는다.
- 교육용 상대 비교라는 안내를 결과 화면에서 항상 볼 수 있게 둔다.
- 탐색 결과를 범위 없이 "전체 최적해", "최적해"처럼 단정하지 않는다. 제한 평가의 결과에는 "제한 평가"임을 표시한다.

### 6.8 창문 편집 (신규)
- **개수:** 창은 2개 이상 6개 이하이다. 2개일 때 삭제를 거부하고, 6개일 때 추가를 거부하며 안내한다(통과 흐름에는 열린 창이 2개 이상 필요하기 때문).
- **고유 ID:** 창마다 고유 ID가 있고 화면에는 "창 A", "창 B"처럼 보인다. 새 창은 현재 쓰이지 않는 가장 앞의 영문 대문자를 받는다(§7 가정 13).
- **배치 규칙(이동·크기 변경·추가가 같은 판정을 쓴다):**
  - 창은 **외벽에만** 둔다(안쪽 벽에는 둘 수 없다).
  - 한 외벽에서 **모서리 부분을 제외한 직선 구간 안**에 있어야 한다. 구간을 벗어나면 거부한다.
  - **같은 외벽의 다른 창과 겹치지 않는다.** 겹침뿐 아니라 맞닿으면 하나의 큰 구멍이 되어 유입과 유출이 붙어 버리므로 **최소 1칸 간격**을 둔다(§7 가정 12).
  - 크기는 최소·최대 범위 안이어야 한다(§7 가정 11).
- **거부 시:** 마지막 유효 상태를 유지하고 짧은 안내를 보여 준다(가구와 같은 방식).
- **조작:** 같은 외벽을 따라 끌어서 옮기고, 끝점을 끌어 크기를 바꾼다. 다른 외벽으로는 벽을 고르는 조작으로 옮긴다. 키보드와 버튼으로도 같은 조작을 할 수 있다(§7 가정 14).
- **추가:** 외벽에서 기본 크기가 들어가는 빈 구간에 놓는다. 기본 크기가 안 들어가면 최소 크기까지 줄여 보고, 그래도 없으면 추가하지 않고 안내한다. 새 창의 기본 개방률은 50%이다(§7 가정 13).
- **삭제:** 창을 삭제하면 그 창의 개구부가 벽으로 돌아온다.
- **계산 반영(확정):** 창을 **드래그하는 동안에는 창의 윤곽만 갱신**하고 유동 계산은 하지 않는다(이전 결과가 보이며 "편집 중"으로 표시). **드래그가 끝난 뒤** 고체 마스크와 경계조건을 갱신해 다시 계산한다. 버튼·키보드·추가·삭제 같은 한 번의 조작은 즉시(짧은 대기 후) 반영한다. 이 구분 때문에 별도의 "계산 적용" 버튼은 두지 않는다.
- 가구와의 관계: 가구는 실내에만, 창은 외벽에만 있어 겹치지 않는다. 가구가 창문 개구부에 맞닿는 것은 허용한다(기존 규칙).

### 6.9 풍향 정의와 표시 (신규)
- **풍향은 바람이 불어오는 방향이다.** 각도는 북쪽 0°, 동쪽 90°, 남쪽 180°, 서쪽 270°로 시계 방향이다. 예: 270°는 서쪽에서 불어온다.
- **평면도의 위쪽이 북쪽**이며 평면도에 **북쪽을 가리키는 화살표("N")** 를 항상 표시한다.
- 풍향 조작부에 **나침반**을 둔다. 나침반에는 두 화살표가 따로 표시된다.
  - **불어오는 쪽**: 바람이 오는 방향(풍향 각도).
  - **이동 방향**: 실제로 공기가 가는 방향(풍향 + 180°).
  - 두 화살표에는 이름표가 붙고, 문장으로도 "서쪽에서 불어와 동쪽으로 이동"처럼 보여 준다.
- **Solver와 화면의 일치:** 화면의 화살표와 계산에 쓰이는 풍향은 **하나의 정의**를 공유한다. 풍향 0°, 90°, 180°, 270°에서 화살표 방향과 유입 창(바람을 정면으로 받는 벽의 창)이 일치해야 한다.
- 실내 공기 흐름은 기존의 "공기 흐름" 요약에 유입 창과 유출 창(여럿일 수 있음)으로 표시한다. 실내 평균 기류 화살표는 후속이다.

## 7. 확정 사항과 가정

### 확정 [사용자 승인]
1. **창문은 2~6개 가변이며, 모두 외벽의 실제 벽 개구부이다.** 기본 평면도는 서로 다른 외벽의 창 2개이다. (개정: "2개 고정"을 대체)
2. **방문은 항상 열린 통로**로 표시하고, 개폐 조작은 이번 범위에 넣지 않는다.
3. **"초기 환기 조건"과 "현재 조건"은 같다.** 곧 사용자가 자동 최적화를 실행하는 시점의 모든 창 개방률과 풍향·풍속 설정이다.
4. **입자 추적 시각화를 우선 구현**하고 유선은 선택이다. 장식용 애니메이션은 쓰지 않는다.
5. **수동 개방률은 0~100%, 5% 단위**이다.
6. **자동 최적화는 기본 5단계(0·25·50·75·100%)** 이며, 조합이 과도하면 **탐색 단계를 축소하거나 탐색할 창을 선택**하게 한다.
7. **창문 위치 이동, 크기 변경, 추가, 삭제**를 제공하고, 창은 외벽에만 두며 서로 겹치거나 벽 범위를 벗어나지 않는다.
8. **창문 편집은 드래그 종료 후 계산에 반영**한다.
9. **풍향은 바람이 불어오는 방향**이고, 평면도에 북쪽 화살표를 표시하며, **실제 바람 이동 방향은 별도 화살표**로 표시한다.
10. **가구 삭제**를 제공한다.
11. **다중 창문 경계조건 원칙:** 기존 2개 창문 모델과 결과를 회귀 기준으로 보존하고, 창별 풍압과 개구부 유량을 개별 계산하는 방식을 쓴다. 기존 Solver 알고리즘은 바꾸지 않는다. 새 모델의 정량 정확도는 검증하지 않는다.
12. **다중 창문 경계조건의 전달과 표시:** 창별 모델 유량을 유입 창에는 유입 속도로, 유출 창에는 압력 고정 경계로 전달한다. 유입 창의 분배는 모델과 같고, 유출 창 사이의 분배는 Solver가 정하므로 모델과 다를 수 있다. 창별 역할·방향·모델 유량·적용 유량을 화면에서 확인할 수 있어야 하며, Solver의 분배를 보정하지 않는다(§6.2).
13. **자동 최적화 결과의 탐색 범위 표시:** 전체 평가와 제한 평가를 구분하고, 실제 사용한 개방률 단계와 평가 조합 수를 표시하며, 제한 평가를 전체 최적해로 표현하지 않는다. 목적함수(잔류율 최소화)는 그대로이다(§6.6).
14. **개방률의 격자 적용 표시:** 설정 개방률과 격자에 적용된 개방률(열린 칸 수·폭)을 구분해 표시하고, 서로 다른 설정이 같은 개구부가 될 수 있음을 안내한다. 기존 격자 처리(반올림·가운데 정렬)는 바꾸지 않는다(§6.2).

### 가정 [구현 전 덮어쓸 수 있음]
1. **환기 취약 후보의 임계값**은 실내 평균 대비 상대 기준이며 정확한 비율은 구현하며 정한다. (기존 가정 5)
2. **조건을 바꾸면 자동으로 재계산**하고, 조합 탐색만 버튼으로 실행한다. (기존 가정 6)
3. **풍속 입력 범위는 약 0~10 m/s**, 풍향은 0~355도(5° 단위)이다. (기존 가정 8)
4. 새 창의 **풍압 규칙**은 기존 단순 규칙(정면 +, 측면 0, 풍하 음수)을 그대로 쓴다.
5. 같은 외벽에 창이 여러 개면 풍압이 같으므로 **그 창들 사이에는 통과 흐름이 없다**(그 외벽의 다른 창과의 압력 차로만 흐른다).
6. 안쪽 벽이 외벽과 만나는 지점에 걸친 창의 흐름은 별도로 검증하지 않는다.
7. 탐색 중에는 화면이 멈추지 않도록 진행률을 보여 준다. (기존 위험 3의 대응 유지)
8. 평면도 위쪽을 북쪽으로 고정한다.
9. 열린 칸 수를 반올림할 때 .5는 올림으로 한다(기존 구현과 같음).
10. **계산 대상 조합 상한은 30개**이다. 이 값은 조합당 계산 시간(Node 약 0.8초, 브라우저 약 2.5초로 측정)에서 정한 것으로, 30개는 약 25~75초이다. 이전의 "9조합 약 30초 이내" 가정을 대체한다.
11. **창 크기**는 최소 4칸(약 0.7 m), 최대 24칸(약 4 m)이다. 새 창의 기본 크기는 16칸(약 2.7 m)이다.
12. **같은 외벽의 창 사이 최소 간격은 1칸**(약 0.17 m)이다. "겹치지 않음"보다 한 칸 엄격하다.
13. **창 ID**는 현재 쓰이지 않는 가장 앞의 영문 대문자(A, B, C, …)이고, 삭제한 ID는 다시 쓸 수 있다. **새 창의 기본 개방률은 50%** 이다.
14. 창을 **다른 외벽으로 옮기는 조작**은 벽 선택 컨트롤로 한다(끌어서 다른 벽에 붙이는 방식은 아님). 개방률은 슬라이더와 함께 **0·50·100% 빠른 선택 버튼**을 유지한다.
15. 탐색 단계 축소는 **자동 제안 후 안내**한다. 사용자가 단계를 직접 바꾸는 조작은 두지 않는다.
16. **탐색할 창 선택**은 조합이 상한을 넘을 때만 나타난다.
17. 가구·창 삭제는 **확인 대화상자와 되돌리기가 없다.**
18. **이동 방향 화살표**는 외부 바람의 방향(풍향 + 180°)이다. 실내 평균 기류 방향은 요약 문구로만 표시한다.
19. 가구가 창문 앞을 막는 것을 편집 단계에서 막지는 않는다(맞닿음 허용). 그 결과(잔류율이 높음)가 그대로 보인다.

## 9. 완료 기준 (관찰 가능)

각 항목은 앱을 실제로 실행해 사람이 확인할 수 있어야 한다.

1. 앱을 열면 가상 평면도와 벽·방문·창문 2개·가구가 보이고, 평면도에 북쪽 화살표가 보인다.
2. 가구를 끌어 이동하고 크기를 바꾸고, 추가·삭제할 수 있다. 다른 가구·벽·아파트 밖·창문·방문 개구부와 겹치는 위치로는 이동·크기 변경·추가가 거부되고 안내가 뜨며, 마지막 유효 배치가 유지된다. 경계가 맞닿는 것은 허용된다. 삭제하면 그 자리의 고체가 사라지고 유동이 다시 계산된다.
3. 각 창의 개방률을 0~100% 범위에서 5% 단위로 설정할 수 있고, 5% 단위가 아닌 값은 입력되지 않는다. 열린 폭이 눈에 띄게 달라지며, **설정 값과 적용 값(열린 칸 수, 열린 폭 m)이 구분되어 표시**된다(예: 길이 16칸 창에서 설정 55% → 적용 56%, 9/16칸).
4. 풍향·풍속을 바꾸면 유입·유출 창문과 흐름이 달라진다. 풍속 0이면 뚜렷한 유입이 없다.
5. 입자는 벽과 가구를 통과하지 않는다. 가구를 옮기면 그 주변으로 돌아 흐른다.
6. 환기 취약 후보 지도가 표시되고, 가구나 창문을 바꾸면 지도도 바뀐다.
7. "최적 조합 탐색"을 누르면 탐색 계획(단계 수, 총 조합 수, 계산 대상 수)이 보이고, 기본 평면도의 창 2개에서는 5단계 25개 조합이 모두 결과에 반영된다. 잔류율이 낮은 상위 3개와 현재 조건의 잔류율이 표에 나온다. 탐색 범위(전체 평가/제한 평가), 사용한 단계, 평가 조합 수가 결과와 함께 표시된다.
8. 1위 조건과 현재 조건의 유동·취약 지도를 나란히 볼 수 있다. 현재 개방률이 탐색 단계에 없는 값(예: 35%)이어도 현재 행이 표시된다.
9. 같은 입력으로 두 번 탐색하면 같은 순위와 잔류율이 나온다.
10. 열린 창이 2개 미만이거나 열린 창의 풍압이 모두 같으면 통과 흐름이 없고 잔류율이 100%이며, 탐색 결과에서도 최하위(동률 포함)이다.
11. 교육용 상대 비교라는 안내가 결과 화면에서 보이고, "검증됨" 등의 표현이 없다.
12. 사용 중 브라우저 네트워크 요청이 외부로 나가지 않는다.
13. 창문을 끌어 옮기고, 끝점을 끌어 크기를 바꾸고, 추가·삭제할 수 있다. 개수는 2개 미만으로 삭제되지 않고 6개를 넘게 추가되지 않으며 안내가 뜬다. 외벽이 아닌 곳, 벽 구간을 벗어난 곳, 같은 외벽의 다른 창과 겹치거나 간격이 1칸 미만인 곳, 허용 크기 밖은 거부되고 마지막 유효 상태가 유지된다. 각 창은 고유 ID를 갖는다.
14. 창문을 드래그하는 동안에는 윤곽만 바뀌고 "편집 중"으로 표시되며 유동은 계산되지 않는다. 놓으면 고체 마스크와 경계조건이 갱신되어 새 유동이 계산되고, 새로 뚫린 개구부로 입자가 지나간다. 이미 나온 탐색 결과는 "조건이 바뀌었습니다"로 표시된다.
15. 서로 다른 외벽의 창이 3개 이상일 때, 각 창이 풍압에 따라 유입 또는 유출 역할을 하고(요약에 유입 창·유출 창이 표시됨), 창의 개방률을 바꾸면 역할과 흐름이 달라진다. 유입량과 유출량의 합이 같다(단위 테스트로 확인).
16. **회귀:** 기본 평면도·기본 가구·서풍 3 m/s에서 창 2개의 개방률 0·50·100% 9개 조합의 잔류율이 개정 전과 소수 다섯째 자리까지 같다(예: 100%/100% = 0.19339, 100%/50% = 0.28123, 50%/100% = 0.36921, 50%/50% = 0.42236, 한쪽이라도 0%면 1.00000).
17. **풍향 표시:** 평면도에 북쪽 화살표가 있고, 나침반에 "불어오는 쪽"과 "이동 방향" 화살표가 따로 있다. 풍향 0°, 90°, 180°, 270°에서 화살표 방향과 유입 창이 일치한다(예: 270°는 서쪽 창으로 들어온다).
18. **탐색 제한:** 창 3개(서로 다른 외벽)에서 5단계 125조합은 3단계 27조합으로 줄어 그 사실이 안내된다. 조합이 2단계로도 상한을 넘으면 탐색할 창을 고르는 선택이 나온다.
19. **창별 흐름 확인:** 창마다 역할(유입·유출·흐름 없음)과 방향, 풍압, 설정·적용 개방률, 모델 유량, 적용 유량이 표시된다. 창 3개 이상에서 유입 창은 모델과 같은 속도로 유입되고, 유출 창이 둘 이상이면 모델 유량과 적용 유량의 차이가 표시된다. 적용 유입량의 합과 적용 유출량의 합은 허용 오차 안에서 같다. 창 2개에서는 모델 유량과 적용 유량이 같다(허용 오차 안).
20. **탐색 범위 표시:** 기본 5단계로 모든 조합을 평가하면 "전체 평가", 단계를 줄이거나 일부 창을 고정하면 "제한 평가"로 표시된다. 제한 평가에는 실제 사용한 개방률 단계(예: 0·50·100%), 평가 조합 수와 5단계 전체 조합 수(예: 27 / 125), 고정한 창과 그 개방률이 표시되고, 추천 문구는 "탐색한 범위 안에서 가장 유리"이며 "전체 최적" 같은 표현이 없다. 상위 3개 표, 추천 문구, 나란히 비교 화면에서 같은 내용이 보인다.
21. **개방률 적용 구분:** 설정과 적용이 다르면 그 사실이 보이고(예: 설정 55% → 적용 56%), 서로 다른 설정이 같은 열린 칸 수가 되는 창에서는 같은 개구부가 되는 설정 범위가 안내된다(예: 길이 16칸 창에서 10~15%는 모두 2칸). 열린 칸 수가 0이 되는 설정(예: 길이 4칸 창의 5%)은 "닫힘"으로 표시된다. 탐색 단계(25% 간격)는 서로 다른 열린 칸 수가 된다.

## 10. 확정된 제약과 이유

- **계산은 모두 로컬 브라우저에서 수행한다.** 외부로 평면도나 입력이 나가지 않게 하려는 보안 제약이다.
- **가상 평면도와 가상 데이터만 쓴다.** 실제 주소·평면도 노출을 막으려는 것이다.
- **MCP, 외부 API, 회사 내부자료, GitHub push·PR·merge, 외부 배포, Claude Hunt 업로드는 사용하지 않는다.** 승인 전까지 로컬에서만 작업한다.
- **정량 검증(유량 불균형, 연속방정식 잔차, 다중 창문 모델의 정확도)은 이번 교육 범위에서 제외한다.** 목적이 기능 연계 가능성 확인이기 때문이다.
- **실제 환기 성능을 검증한 것처럼 표현하지 않는다.** PRODUCT.md의 제품 경계이다.
- **기존 검증을 마친 Solver, Passive Scalar 수송, 자동 최적화 목적함수는 유지한다.** 개정이 이를 흔들면 회귀이며, 창 2개 결과가 달라지면 안 되는 이유이다.

## 11. 건드리지 않는 영역과 이유

- `PRODUCT.md`: 읽기만 한다. 반영 여부는 별도로 정한다.
- **Solver와 Passive Scalar 로직, 목적함수**: 이번 개정의 구현에서도 알고리즘을 바꾸지 않는다. 다중 창문 모델은 Solver에 넘기는 경계조건을 만드는 부분에만 영향을 준다. 개방률을 열린 칸으로 바꾸는 기존 격자 처리(반올림·가운데 정렬)도 바꾸지 않는다.
- 프로젝트 설정과 스킬 파일: 이번 작업과 무관하다.
- 외부 서비스·원격 저장소: 보안 제약에 따라 사용하지 않는다.

## 12. 보류 항목과 남은 위험

- 환기 취약 후보의 정확한 임계값, 계산 시간(스텝 수), 격자 해상도: 구현 중 §9의 완료 기준을 만족하게 맞춘다. 구현 세부이다.
- 창별 흐름 표, 탐색 범위 표시, 설정·적용 개방률 표시의 화면 배치와 문구 세부: 구현 중 §9의 19~21을 만족하게 정한다.
- **후속 후보:** 창 이동 중 실시간 유동 미리보기, 가구·창 삭제 되돌리기, 실내 평균 기류 화살표, 창을 끌어서 다른 외벽으로 옮기기, 안쪽 벽과 외벽 접합부에 걸친 창의 해석.
- 남은 위험: 단순화한 창문 경계조건(특히 창이 3개 이상일 때 유출 분배) 때문에 상위 3개 순위가 현실과 다를 수 있다. 이는 교육용 상대 비교 안내로 다룬다.
