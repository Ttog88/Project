# Apartment Airflow Optimizer — 첫 번째 구현 스펙

> **상태: 확정 (사용자 승인 완료).** 전체 개발 방향과 기능 범위를 사용자가 승인했고, §7의 [확정] 항목 세 가지(창문 배치, 현재 조건의 정의, 입자 추적 우선)를 확인했다. §7의 나머지 "가정"은 요청에 없던 부분을 채운 기본값이라 구현 중 사용자가 덮어쓸 수 있다.

앱 전체의 전제는 [PRODUCT.md](../../../PRODUCT.md)가 소유한다. 이 문서는 그중 이번 작업 단위에 해당하는 부분만 다룬다. 일반 UI 구성 원칙은 [ui-composition](../../decisions/ui-composition.md)을 따른다. 이 문서에서는 유동 시각화 캔버스에는 custom UI를 쓸 수 있고, 그 주변의 일반 컨트롤은 같은 계약의 shadcn 구성을 유지한다는 부분을 적용한다.

## 1. 이번 작업의 목표

사용자가 가상 아파트 평면도에서 가구 위치, 창문 개방률, 풍향·풍속을 바꾸면 2D 경량 유체 계산이 유동장을 다시 계산한다. 여러 창문 개방 조합을 자동으로 비교해 상대적으로 환기가 유리한 조건을 추천하는 **작동형 프로토타입**을 만든다.

목적은 경량 유동 Solver와 자동 최적화를 연결할 수 있는지 확인하는 것이다. 실제 환기 성능이나 CFD 수준의 정량 정확도를 검증하는 것은 목적이 아니다.

## 2. PRODUCT.md와의 충돌 확인

**제품 방향을 바꿔야 하는 충돌은 없다.** 확인 결과는 다음과 같다.

| 항목 | 판정 | 내용 |
|---|---|---|
| 목적·사용자·핵심 루프 | 일치 | 요청한 목표와 PRODUCT.md의 정의·핵심 루프가 같은 방향이다. |
| 오늘 MVP 5개 기능 | 일치 | 필수 기능 12개는 PRODUCT.md의 MVP 5개를 세분화한 것이다. |
| 정량 검증 제외 | 일치 | 질량보존 잔차 등의 정량 검증 제외는 PRODUCT.md의 "정량 정확도 검증은 후속"과 같다. |
| 물리 일관성 | 일치 | 불투과 경계, 입자가 속도장을 사용, 조건 변경 시 재계산은 PRODUCT.md의 Physical consistency rules 그대로다. |
| 보안 제약 | 일치 | PRODUCT.md의 제약과 같거나 더 구체적이다. |
| 선택 기능 | 일치 | 이미지 업로드와 기상청 CSV는 PRODUCT.md의 "조건부 포함, 후속 분리 가능"에 해당한다. |
| PRODUCT.md의 Unknown | **이 스펙이 해소** | "상대적으로 유리한 조합의 점수 정의"는 추적 물질 잔류율로, "이미지·CSV 포함 여부"는 이 문서의 §5로 정해졌다. PRODUCT.md는 이번 단계에서 수정하지 않았다. 승인 후 별도 단계에서 반영 여부를 정한다. |

용어 차이 1건이 있다. PRODUCT.md는 "환기 취약 후보 구역", 이번 요청은 "추적 물질 잔류율"이라고 쓴다. 같은 계산에서 나오는 두 결과로 구분한다. **잔류율은 조건 전체를 비교하는 점수**이고, **환기 취약 후보는 한 조건 안에서 실내 어디가 취약한지 보여 주는 지도**다.

| 구분 | 항목 | 판단 |
|---|---|---|

| **필수** | 창문 2개, 개방률 0/50/100%, 풍향·풍속 수동 설정 | 구현 가능. 이산 3단계이고 입력 UI도 단순하다. |
| **필수** | Stable Fluids 계산, 속도장 기반 입자 시각화 | 구현 가능하나 **가장 큰 작업**이다. 경계조건과 벽 누설 방지가 핵심이다. |
| **필수** | Passive Scalar 잔류율, 환기 취약 후보 지도 | 구현 가능. 같은 계산 위에 얹는다. |
| **필수** | 9개 조합 전수탐색, 상위 3개와 현재 조건 비교 | 구현 가능. 계산 시간이 병목이 될 수 있다(§8의 위험 3). |
| **선택, 오늘 시도 가능** | 가상 기상조건 프리셋(계절별 풍향·풍속) | 값을 입력칸에 채워 넣는 수준이라 저비용이다. 필수 완료 뒤 시간이 남으면 포함한다. |
| **선택, 오늘 시도 가능** | 벽·창문·방문 수동 보정 | 중간 난이도. 가구 편집이 끝난 뒤 시간이 남을 때만 시도한다. |
| **선택, 오늘 제외 권고** | 지역·아파트 방향 설정 | 풍향을 평면도 기준으로 직접 입력하므로 오늘은 필요 없다. 후속으로 둔다. |
| **선택, 오늘 제외 권고** | 사용자 평면도 이미지 업로드 | 벽·창 자동 인식이 어렵고 필수 흐름을 막을 수 있다. 오늘은 제외한다. |
| **선택, 오늘 제외 권고** | 기상청 CSV 불러오기 | 인코딩, 컬럼, 풍향 규약을 정해야 한다. 오늘은 제외하고 가상 프리셋으로 대체한다. |

**시간 판단:** 필수 12개는 2~3시간에 빠듯하지만 가능한 범위다. 시간이 부족해지면 아래 순서로 줄인다. ① 선택 기능 전부 → ② 유선 표시(입자만 유지) → ③ 가구 크기 변경(이동만 유지).

## 4. 첫 번째 사용자 결과

사용자가 앱을 열면 **가상 아파트 평면도**가 보이고, 벽·방문·창문 2개·가구 몇 개가 표시된다. 이 상태에서 사용자는 다음을 할 수 있다.

1. 가구를 끌어서 옮기거나 크기를 바꾼다. 풍향·풍속을 입력하고, 두 창문의 개방률을 0%·50%·100% 중에서 고른다.
2. 조건을 바꾸면 곧바로 유동이 다시 계산되고, 평면도 위에서 입자가 계산된 속도장을 따라 움직인다. 벽과 가구를 통과하지 않고 돌아 흐른다.
3. 같은 조건에서 "환기 취약 후보" 지도가 표시되어, 공기가 잘 안 바뀌는 구역이 어디인지 볼 수 있다.
4. "최적 조합 탐색"을 누르면 9개 조합이 같은 조건에서 계산되고, **잔류율이 낮은 상위 3개**가 현재 조건과 함께 표로 나온다.
5. 1위 조건과 현재 조건을 나란히 놓고 유동과 취약 후보 지도를 비교한다. 화면에는 "교육용 상대 비교이며 실제 환기 성능을 검증한 것이 아니다"라는 안내가 항상 보인다.

## 5. 승인 범위

### 필수 (이번 작업의 완료 조건)

1. 가상의 2D 아파트 평면도 1개 제공
2. 벽, 방문, 창문 위치 표시
3. 가구 이동 및 크기 변경
4. 벽과 가구를 유동 계산의 고체 영역으로 반영
5. 창문 2개, 개방률 0%·50%·100% 설정
6. 풍향·풍속 수동 설정
7. 2D Stable Fluids 기반 유동장 계산
8. 계산된 속도장을 이용한 유동 시각화
9. Passive Scalar 수송을 이용한 환기 취약 후보 분석
10. 창문 개방 조합 자동 전수탐색
11. 추적 물질 잔류율 기준의 상대적 추천
12. 최적 조건과 현재 조건의 결과 비교

### 선택 (오늘 구현은 보장하지 않음)

- 가상 기상조건 프리셋, 벽·창문·방문 수동 보정: 필수 완료 후 시간이 남을 때만 포함한다.
- 지역·아파트 방향, 평면도 이미지 업로드, 기상청 CSV: 오늘은 제외하고 후속으로 둔다(§3의 판단).

### 이번 범위 밖

일사·복사열, 3D 해석, 정량 정확도 검증(유량 불균형, 연속방정식 잔차 포함), 실제 주소·평면도 사용, 외부 서비스 연동.

## 6. 동작 계약

### 6.1 평면도와 장애물
- 평면도는 하나이며 벽, 방문, 창문 2개가 구분되어 보인다. 창문 2개는 교차환기를 비교할 수 있도록 서로 다른 외벽에 배치한다. 각 창문은 해당 외벽에 난 실제 개구부로 처리되어, 열린 만큼 벽이 뚫리고 닫힌 만큼 벽으로 막힌다(확정, §7).
- 벽과 가구는 유동이 통과할 수 없는 고체이다. 가구를 옮기거나 크기를 바꾸면 고체 영역이 즉시 갱신된다.
- 가구는 사각형이고, 벽 안쪽 실내에서만 움직이고 크기를 바꿀 수 있다(벽·다른 가구와 겹치지 않는지는 가정에 둔다).

### 6.2 창문과 바람
- 두 창문은 각각 0%, 50%, 100% 중 하나로 설정한다. 0%는 막힌 벽과 같고, 50%는 열린 폭이 절반, 100%는 전체가 열린 상태이다.
- 풍향은 평면도 기준 방향(도 단위), 풍속은 수동 입력한다.
- 바람이 불어오는 쪽 창으로는 공기가 들어오고, 반대쪽 창으로는 나간다. 개방률이 클수록 더 많이 흐르고, 바람과 창문 방향이 어긋날수록 적게 흐른다.

### 6.3 유동 계산
- 2D 비압축성 Stable Fluids로 계산하고, 고체 경계에서는 불투과 조건을 적용한다.
- 가구, 창문 개방률, 풍향·풍속이 바뀌면 계산영역과 경계조건을 갱신해 다시 계산한다.
- 질량보존을 정량 검증하지는 않지만, 기본적인 질량보존 구조(속도장의 발산을 줄이는 처리)와 벽면 불투과는 유지한다.

### 6.4 시각화
- 입자는 계산된 속도장을 따라 움직인다. 속도장과 무관한 장식용 움직임은 쓰지 않는다.
- 벽·가구 안으로 들어가는 입자는 없다.
- 유동 시각화는 Solver가 계산한 속도장을 이용한 입자 추적을 우선 구현하며, 이것으로 필수 시각화를 충족한다. 유선은 선택 요소이다(확정, §7).

### 6.5 환기 취약 후보 분석
- 계산 시작 시 실내 모든 유체 영역에 같은 농도의 추적 물질을 채우고, 창문으로 들어오는 공기의 농도는 0으로 한다.
- 정해진 계산 시간이 지난 뒤 남아 있는 농도가 높은 구역을 "환기 취약 후보"로 지도에 표시한다.
- 표시 기준은 실내 평균 대비 상대 기준이며 정확한 임계값은 가정이다(§7).

### 6.6 자동 탐색과 추천
- 창문 2개 × 개방률 3단계 = **9개 조합**을 전수 탐색한다.
- 모든 조합은 같은 가구 배치, 같은 풍향·풍속, 같은 초기 농도, 같은 계산 시간으로 비교한다.
- 목적함수는 정해진 시간 뒤 **추적 물질 잔류율(남은 총량 ÷ 처음 총량)이 낮을수록 유리**하다는 것이다.
- 결과는 잔류율이 낮은 상위 3개와 현재 조건을 한 표로 보여 준다. 각 행에 두 창문의 개방률과 잔류율, 현재 조건 대비 차이를 표시한다.
- **현재 조건**은 사용자가 자동 최적화를 실행하는 시점에 설정되어 있는 창문 개방률과 풍향·풍속이다. 최적화 결과는 이 현재 조건과 비교한다(확정, §7).
- 최적 조건과 현재 조건을 나란히 놓고 유동과 취약 후보 지도를 비교한다.
- 같은 입력이면 항상 같은 결과가 나온다.

### 6.7 표현 원칙
- 결과는 "상대적으로 유리한 조건"으로만 표현한다. "환기 성능이 검증되었다", "실제 아파트에서 X% 개선된다" 같은 표현은 쓰지 않는다.
- 교육용 상대 비교라는 안내를 결과 화면에서 항상 볼 수 있게 둔다.

## 7. 확정 사항과 가정

[확정]으로 표시한 항목(1, 3, 4번)은 사용자가 승인한 결정이다. 나머지는 요청에 없던 부분을 채운 기본값이며, 구현 중 사용자가 덮어쓸 수 있다.

1. **[확정] 창문은 2개이며 서로 다른 외벽에 있는 실제 벽 개구부이다.** 그래야 교차환기 비교가 가능하고 풍향에 따라 유입·유출이 바뀌며 9개 조합 비교가 의미를 갖는다. 3개로 늘리면 조합이 27개가 된다.
2. **방문은 항상 열린 통로**로 표시하고, 개폐 조작은 이번 범위에 넣지 않는다.
3. **[확정] "초기 환기 조건"과 "현재 조건"은 같다.** 곧 사용자가 자동 최적화를 실행하는 시점의 창문 개방률과 풍향·풍속 설정이다. 앱을 처음 열었을 때의 기본값과 별도로 저장하지 않는다.
4. **[확정] 입자 추적 시각화를 우선 구현**하고 유선은 선택이다. 입자는 계산된 속도장을 이용하며, 장식용 애니메이션은 쓰지 않는다.
5. **환기 취약 후보의 임계값**은 실내 평균 잔류 농도보다 높은 구역 중 상대적으로 높은 일부로 하고, 정확한 비율은 구현하며 정한다.
6. **조건을 바꾸면 자동으로 재계산**하고, 9개 조합 탐색만 버튼으로 실행한다.
7. **9개 탐색은 일반 노트북에서 약 30초 이내**에 끝난다. 이를 넘기면 격자 해상도를 낮춘다(§8).
8. **풍속 입력 범위는 약 0.5~10 m/s**, 풍향은 0~359도로 한다.

## 9. 완료 기준 (관찰 가능)

각 항목은 앱을 실제로 실행해 사람이 확인할 수 있어야 한다.

1. 앱을 열면 가상 평면도와 벽·방문·창문 2개·가구가 보인다.
2. 가구를 끌어 이동하고 크기를 바꿀 수 있고, 바꾸면 유동이 다시 계산되어 입자 흐름이 달라진다.
3. 두 창문을 각각 0·50·100%로 바꿀 수 있고, 50%는 100%보다 열린 폭이 눈에 띄게 좁다.
4. 풍향·풍속을 바꾸면 유입·유출 창문과 흐름이 달라진다. 풍속 0이면 뚜렷한 유입이 없다.
5. 입자는 벽과 가구를 통과하지 않는다. 가구를 옮기면 그 주변으로 돌아 흐른다.
6. 환기 취약 후보 지도가 표시되고, 가구나 창문을 바꾸면 지도도 바뀐다.
7. "최적 조합 탐색"이 9개 조합을 모두 계산하고, 잔류율이 낮은 상위 3개와 현재 조건의 잔류율이 표에 나온다.
8. 1위 조건과 현재 조건의 유동·취약 지도를 나란히 볼 수 있다.
9. 같은 입력으로 두 번 탐색하면 같은 순위와 잔류율이 나온다.
10. 두 창문을 모두 0%로 하면 흐름이 없고 잔류율이 가장 높게 나온다(탐색 결과에서도 최하위).
11. 교육용 상대 비교라는 안내가 결과 화면에서 보이고, "검증됨" 등의 표현이 없다.
12. 사용 중 브라우저 네트워크 요청이 외부로 나가지 않는다.

## 10. 확정된 제약과 이유

- **계산은 모두 로컬 브라우저에서 수행한다.** 외부로 평면도나 입력이 나가지 않게 하려는 보안 제약이다.
- **가상 평면도와 가상 데이터만 쓴다.** 실제 주소·평면도 노출을 막으려는 것이다.
- **MCP, 외부 API, 회사 내부자료, GitHub push·PR·merge, 외부 배포, Claude Hunt 업로드는 사용하지 않는다.** 승인 전까지 로컬에서만 작업한다.
- **정량 검증(유량 불균형, 연속방정식 잔차)은 이번 교육 범위에서 제외한다.** 목적이 기능 연계 가능성 확인이기 때문이다.
- **실제 환기 성능을 검증한 것처럼 표현하지 않는다.** PRODUCT.md의 제품 경계이다.

## 11. 건드리지 않는 영역과 이유

- `PRODUCT.md`: 이번 단계에서는 읽기만 한다. 스펙이 정한 두 가지(점수 정의, 선택 기능 포함 여부)는 승인 후 별도로 반영 여부를 정한다.
- 프로젝트 설정과 스킬 파일: 이번 작업과 무관하다.
- 외부 서비스·원격 저장소: 보안 제약에 따라 사용하지 않는다.

## 12. 보류 항목과 남은 위험

- 환기 취약 후보의 정확한 임계값, 계산 시간(스텝 수), 격자 해상도: 구현 중 §9의 완료 기준을 만족하게 맞춘다. 정해진 값은 승인된 스펙의 결정이 아니라 구현 세부이다.
- 가구가 서로 겹치거나 벽과 겹칠 때의 처리: 가정이며, 사용자가 다른 동작을 원하면 알려 달라.
- 남은 위험: 단순화한 창문 경계조건 때문에 상위 3개 순위가 현실과 다를 수 있다. 이는 교육용 상대 비교 안내로 다룬다.
